# Feedback and contributions

Use issues for reproducible bugs, feature requests, or feedback on the public demo. Documentation improvements are welcome as pull requests.

For a bug, include the page, browser/device, reproduction steps, expected result, and actual result. Redact personal information from screenshots. Never include passwords, verification codes, API keys, session cookies, or private generated content.

For a feature request, explain your workflow and the problem it would solve. The production source is private, so application-code contributions are not accepted through this showcase.

Security reports should follow [SECURITY.md](SECURITY.md), not public issues.
